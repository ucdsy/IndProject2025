## 原 A/B 口径多输出扩展复跑（v2）

v1 的 `A_multi direct set` 更像直接集合选择器，实验数值较高，但与冻结主线强调的 Stage A/Stage B 协作口径不完全一致。v2 改为“原 Stage A/Stage B 的多输出扩展”：

- Stage A_multi v2 先运行原 Stage A clean，保留 `score_a`、`score_related`、margin、confidence 和 escalation reasons，再让 LLM 做逐候选 `task_fit/select_fit` 裁决，最后融合为 `score_set`。
- Stage B_multi v2 采用 expanded gate，融合 Stage A 校准先验、异构 reviewer 支持/移除票、reviewer 置信度和 Stage R 分数，边界接近时支持第二轮复核。

## 补强对比基线（2026-06-02）

为避免只与“规则路由、规则+协作、单智能体结构化语义路由、单智能体+协作”比较，本轮补充四组独立 baseline。`Flat LLM` 两组仍使用 Stage R Top-10 作为候选来源，但 prompt 只暴露 `query/context + candidate FQDN + desc + aliases`，不暴露 Stage R 分数、结构化字段、层级约束或 A/B 的中间判别字段。

该组结果显示，传统词面检索和 embedding 检索不能充分解决多意图集合路由；但“Stage R 候选 + 扁平 LLM 选择”已经是强基线，尤其 self-consistency 版本超过当前 `A_multi direct set` 和 `A_multi v2 + B_multi v2 hetero`。因此论文中不宜再表述为“简单 LLM 选择候选无法达到该效果”，更稳妥的表述是：结构化语义判别与职责化复核在可解释性、可审计性、与冻结主线一致性上更强，但多意图集合精度目前还需要继续超过 flat LLM self-consistency 这一强基线。

## 结果解读

Stage R 的候选召回已经较高，Top-10 覆盖 97.76% 的 gold intent，95.00% 的样本实现 gold 全覆盖，因此当前主要瓶颈不在候选构建，而在集合选择阶段。

相对 A_clean，`A_llm + related_v2_llm` 显著提升集合指标，SetF1_micro 从 0.4794 提升到 0.8134，ExactSetAcc 从 0.1333 提升到 0.5750。进一步将任务改为直接集合路由后，`A_multi direct set` 达到 ExactSetAcc 0.6917、SetF1_micro 0.8470，说明多意图任务不宜再通过 primary/related 后处理间接表达，而应直接输出集合。

v2 复跑更贴近冻结主线的 A/B 结构：Stage A_multi v2 不再是单纯 direct set，而是基于原 Stage A 候选分数和 LLM 逐候选判断进行校准；Stage B_multi v2 也不再几乎跳过，expanded gate 触发 100/120 条。结果上，B_multi v2 将 Stage A_multi v2 的 ExactSetAcc 从 0.5833 提升到 0.6333，SetF1_micro 从 0.8092 提升到 0.8251，说明多智能体复核对多输出集合有正向修正。

同时，v2 full chain 仍低于旧 `A_multi direct set` 的 0.6917/0.8470。这说明当前 faithful-A/B 版本更适合支撑“多智能体协作链路”论述，但若单纯追求多意图集合指标，direct set 版本仍是更强基线。后续若要正式写论文，应把 v1 direct set 作为直接集合选择上界/强基线，把 v2 作为与冻结主线一致的协作式实现，并进一步调 Stage A set calibration 和 Stage B add/remove 阈值。

补强 baseline 进一步改变了结论边界：`Flat LLM selector + self-consistency` 达到 ExactSetAcc 0.7167、SetF1_micro 0.8930，已经超过当前所有 A/B multi 链路。这说明多意图任务的论文叙事不能只强调“多智能体一定优于单 LLM”，而应改为更精确的论述：Stage R 候选召回足够高后，扁平 LLM 可以形成很强的集合选择基线；多智能体协作链路若要作为效果最优方案，还需要在该强基线上继续加入职责化复核，或把当前 v2 定位为“与冻结 primary 主线一致、可解释可审计的协作实现”，而不是最终精度最优实现。
